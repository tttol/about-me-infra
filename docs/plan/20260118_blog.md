# blog.about-tttol.link サブドメイン追加計画

## 概要

既存の `about-tttol.link` に加えて、`blog.about-tttol.link` でブログサイトをホスティングする。

## 前提条件

- Route 53で `about-tttol.link` のホストゾーンが既に存在
- サブドメインは同一ホストゾーン内で管理可能（新規取得不要）

## 実施手順

### 1. ACM証明書の準備（us-east-1）

ワイルドカード証明書（`*.about-tttol.link`）を新規作成する。これにより、今後のサブドメイン追加時に証明書の再作成が不要になる。

#### 1-1. 証明書のリクエスト

AWSコンソールまたはAWS CLIで証明書を作成する。

**AWSコンソールの場合:**
1. AWS Certificate Manager（us-east-1リージョン）を開く
2. 「証明書をリクエスト」をクリック
3. 「パブリック証明書をリクエスト」を選択
4. ドメイン名に以下を入力:
   - `about-tttol.link`（メインドメイン）
   - `*.about-tttol.link`（「この証明書に別の名前を追加」で追加）
5. 検証方法: 「DNS検証」を選択
6. 「リクエスト」をクリック

**AWS CLIの場合:**
```bash
aws acm request-certificate \
  --domain-name "about-tttol.link" \
  --subject-alternative-names "*.about-tttol.link" \
  --validation-method DNS \
  --region us-east-1
```

#### 1-2. DNS検証

証明書リクエスト後、ACMがDNS検証用のCNAMEレコードを生成する。

**AWSコンソールの場合:**
1. ACMで作成した証明書を選択
2. 「Route 53でレコードを作成」ボタンをクリック（自動でCNAMEレコードが追加される）

**AWS CLIの場合:**
```bash
# 証明書のARNを取得
CERT_ARN=$(aws acm list-certificates --region us-east-1 \
  --query "CertificateSummaryList[?DomainName=='about-tttol.link'].CertificateArn" \
  --output text)

# 検証用のCNAME情報を取得
aws acm describe-certificate --certificate-arn $CERT_ARN --region us-east-1 \
  --query "Certificate.DomainValidationOptions"
```

出力されたCNAME名とCNAME値をRoute 53に登録する。

#### 1-3. 検証完了の確認

```bash
# ステータスが ISSUED になるまで待機
aws acm describe-certificate --certificate-arn $CERT_ARN --region us-east-1 \
  --query "Certificate.Status"
```

ステータスが `ISSUED` になれば検証完了。通常5〜30分程度かかる。

#### 1-4. 既存CloudFrontの証明書を更新

新しいワイルドカード証明書のARNを `.env` に設定し、既存の `about-tttol.link` サイトにも適用する。

```bash
# .envファイルを更新
ACM_CERTIFICATE_ARN=arn:aws:acm:us-east-1:<ACCOUNT_ID>:certificate/<NEW_CERT_ID>
```

この時点で `cdk deploy` すると、既存のCloudFrontの証明書が更新される（ダウンタイムなし）。

### 2. CDKスタックの修正

`lib/about-me-infra-stack.ts` に以下を追加:

```typescript
// ブログ用S3バケット
const blogBucket = new s3.Bucket(this, 'BlogBucket', {
  bucketName: `blog-about-me-infra-${this.account}`,
  publicReadAccess: false,
  blockPublicAccess: s3.BlockPublicAccess.BLOCK_ALL,
  removalPolicy: cdk.RemovalPolicy.DESTROY,
  autoDeleteObjects: true,
  encryption: s3.BucketEncryption.S3_MANAGED,
});

// ブログ用CloudFront Distribution
const blogDistribution = new cloudfront.Distribution(this, 'BlogDistribution', {
  defaultBehavior: {
    origin: origins.S3BucketOrigin.withOriginAccessControl(blogBucket),
    viewerProtocolPolicy: cloudfront.ViewerProtocolPolicy.REDIRECT_TO_HTTPS,
    cachePolicy: cloudfront.CachePolicy.CACHING_OPTIMIZED,
    compress: true,
  },
  domainNames: [`blog.${props.domainName}`],
  certificate: certificate, // ワイルドカード証明書を使用
  defaultRootObject: 'index.html',
  errorResponses: [
    {
      httpStatus: 404,
      responseHttpStatus: 200,
      responsePagePath: '/index.html',
    },
    {
      httpStatus: 403,
      responseHttpStatus: 200,
      responsePagePath: '/index.html',
    },
  ],
});

// ブログ用Aレコード
new route53.ARecord(this, 'BlogAliasRecord', {
  zone: hostedZone,
  recordName: 'blog',
  target: route53.RecordTarget.fromAlias(
    new targets.CloudFrontTarget(blogDistribution)
  ),
});

// Output
new cdk.CfnOutput(this, 'BlogURL', {
  value: `https://blog.${props.domainName}`,
  description: 'Blog Domain URL',
});
```

### 3. 環境変数の確認

ステップ1-4で `.env` の `ACM_CERTIFICATE_ARN` をワイルドカード証明書のARNに更新済みであることを確認。

### 4. デプロイ

```bash
# 差分確認
npm run cdk diff

# デプロイ
npm run cdk deploy
```

### 5. 動作確認

- `https://blog.about-tttol.link` にアクセスして表示確認
- SSL証明書が正しく適用されていることを確認

## 注意事項

- ACM証明書は必ず **us-east-1** リージョンで作成すること（CloudFrontの要件）
- 証明書のDNS検証完了まで数分〜数十分かかる場合がある
- 既存の `about-tttol.link` サイトに影響がないことをデプロイ前に `cdk diff` で確認
